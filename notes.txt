Summary (what you all agreed on)
Build a newsletter product where users land on a site, opt in with email, and receive a weekly or monthly “tool updates + comparison” digest. The backend runs an agent that checks updates for a chosen category (start with top IDEs), compares them, pulls in supplemental non-vendor sources (because vendor changelogs can be biased/surface-level), and sends a clean “pros/cons + recommendation” email. Then you seed it with your squad’s emails, collect feedback, and expand distribution (DevColor, other Slack channels) and expand categories beyond IDEs.

Agent Plan (MVP → scalable system)
0) MVP scope (keep it tight)
Category: IDEs only
Tools to track (example set): VS Code, JetBrains (IntelliJ), Cursor, Visual Studio, Neovim (or replace with “Zed” depending on your target audience)
Cadence: monthly first (less pressure), then weekly if it’s stable
Output: 1 email per cycle with: updates, pros/cons, “who it’s for”, final recommendation

The Agents (roles + inputs/outputs)
Agent 1 — Source Collector (Update Harvester)
Goal: gather new info since last run.
Inputs: tool list + time window + known source URLs.
Sources:
Vendor changelogs / release notes (official)  * priority 


Backlog Supplemental sources (non-vendor): GitHub releases, reputable blogs, dev newsletters, (Reddit/HN threads (lightly), issue trackers (signals), benchmark posts (when credible)
Output (structured):
Per tool: {highlights[], breaking_changes[], notable_fixes[], version, release_date, links[]}

Backlog - Agent 2 — Credibility & De-bias Filter
Goal: don’t let marketing fluff dominate.
Logic:
Prefer: official notes for facts (version/features), third-party for impact (stability, DX, complaints, perf)
Down-rank: pure promo posts, vague claims with no evidence
Output:
“Evidence ledger” per tool with confidence tags: high/med/low, plus citations/links list.

Agent 3 — Comparator (Pros/Cons + Tradeoffs)
Goal: compare the set consistently.
Comparison rubric (fixed headings):
Speed/perf
Language support & debugging
Extensions/plugin ecosystem
AI features (if relevant)
Remote dev/containers
Reliability/stability
Pricing/licensing
Best-fit personas (beginner, enterprise, polyglot, etc.)
Output:
A normalized comparison object + short “decision rules”

Agent 4 — Recommender (Audience-aware) - High Priority
Goal: make a recommendation that isn’t cringe.
Inputs: comparator output + (optional) audience segment choices (e.g., “backend Python dev”, “student”, “enterprise team”).
Output:
“If you’re X, pick Y” recommendations
“Avoid if…” caveats
One default pick + 1–2 alternatives

Agent 5 — Newsletter Writer (Formatter + Tone)
Goal: turn structured data into an email people actually read.
Output sections:
TL;DR (5 bullets max)
Biggest changes this cycle
IDE-by-IDE updates (short)
Comparison table in text form (no giant tables)
Recommendation + who it’s for
Links / references

Agent 6 — QA / Safety / Hallucination Guard (Backlog)
Goal: block bad sends.
Checks:
Every claim must map to a source link or be labeled “inference”
No invented versions/dates
No defamatory language (“X is trash”)—keep it professional
Output: pass/fail + list of fixes.

Orchestration Pipeline (end-to-end)
Scheduler triggers run (weekly/monthly)

Filter scores credibility → evidence ledger
Comparator builds rubric output
Recommender generates picks

Store artifacts (newsletter HTML/text + structured JSON + sources) for future diffs

Prompting approach (practical, not fancy)
Use strict JSON contracts between agents so you can debug.
Collector prompt pattern
“Return only JSON. Include version/date only if explicitly stated in sources. Provide links.”
Comparator prompt pattern
“Use this fixed rubric. If no evidence, say ‘unknown’.”
Writer prompt pattern
“Write for software engineers. No marketing tone. Short paragraphs. Bullet-heavy. Link the sources at the end.”
